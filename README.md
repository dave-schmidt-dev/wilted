## Git hooks

Install the repository-owned hooks once per clone:

```bash
make install-hooks
```

The `pre-commit` hook runs `make check-fast` (runtime lint and dead-code
checks). The `pre-push` hook runs `make validate`, then compares each pushed
ref with the last green Mac UI receipt in `.logs/native-ui-receipt.json` for
the paths in `scripts/mac-ui-surface.paths`. A Mac UI surface change requires
`make native-ui` on a clean commit; non-surface pushes remain headless. The
installer is idempotent and sets the installing worktree's private
`core.hooksPath` to its `.githooks`, so installing in one linked worktree does
not change its siblings. A legacy shared `.githooks` setting is migrated only
when this is the sole worktree; with linked siblings, installation refuses
without changing Git configuration.

## Scope

Larder is the one place kept episodes wait. The active podcast appears in Now Playing instead of a second Ready row; the durable queue retains its position for playback succession. Larder groups waiting episodes as Ready, Needs preparation, and Not downloaded, and shows a completed preparation summary only when a successful terminal journal matches the audio revision currently ready to play. A transcript by itself or a journal for an older revision is not presented as prepared.

The active milestone turns the native SwiftUI Mac app into a daily driver. The existing article path stays intact; the milestone adds subscribed feeds, cancellable local episode downloads with visible progress, atomic enclosure imports, a durable Larder listening queue, continuous playback, direct seeking, persistent speed, and exact resume. Feeds, episodes, queue state, playback speed, and episode checkpoints remain local-only until Phase 3 Mac owner acceptance. The existing iOS listener and article CloudKit path remain unchanged while that Mac milestone is implemented and qualified.

Navigation is a destination switch on both platforms. The Mac sidebar lists Larder, Feeds, and Settings, in that order. Feeds is a one-decision inbox: Keep moves an episode to Larder and Skip moves it to the collapsed Off the list section. Refresh adds metadata only, exposes live progress and Cancel, and records the last successful refresh; undecided episodes never start download or preparation. Larder owns downloading, preparing, sorting, playback, and queue order. Its Add article action stays reachable when the article list is empty or a search has no article matches. Its independent **Group by** control offers Feed, Date, and Status, while **Sort by: Custom order** offers Custom order, Newest, Oldest, Length, Show, and Title; each row shows its release date. Drag and drop switches back to Custom order and draws the exact insertion gap. Play Now inserts the selected episode at the current slot and leaves the interrupted episode immediately next. Ready episodes play from top to bottom while non-ready rows are skipped. Now Playing is embedded in Larder and remains an always-visible bottom rail elsewhere; Transcript and Notes open inline in Larder and in the full-window player elsewhere. Settings exposes appearance plus feed refresh, processing schedule, transcript, and ad-removal defaults; admitted work keeps the policy snapshot it started with. Settings also offers a quiet chime, on by default, at each spot an advertisement was cut; it plays over the audio, so switching it needs no re-preparation. iPhone exposes Larder, Now Playing, and Settings as tabs. A dated Mac verification report is required before a major build or rollup deployment, while local debug installations use their own gate evidence; neither claims owner acceptance.

Skip is reversible. Skipped and retired episodes remain stored and appear under Feeds' collapsed **Off the list** section, where Restore clears the stored removal without a feed fetch or rematch. Removing a row from Larder is different: it only removes queue membership and preserves downloads, prepared cuts, transcripts, and listening history. Store version 13 owns one `removalKind` column that says an episode is retired, dismissed, or neither, while downloaded podcast revision identity includes both the episode and verified content hash so identical bytes from different episodes cannot collide. Existing content-hash-only podcast revisions remain readable and are reused only for the same item and exact hash; article and TTS revision identity is unchanged.

Finishing or skipping an episode retires it from Larder into Feeds' Off the list section. Retirement does not delete the episode row, download, transcript, prepared cut, or listening history. On launch, the retirement sweep also repairs completed episodes left active by an earlier build. A revisionless legacy completion retires when its current ready audio predates completion; a later re-download remains active. A store still carrying the pre-V13 separate dismissal-tombstone table folds each tombstone onto its episode row (recreating the row as a placeholder if it was already gone) through the same idempotent post-open reconciliation that repairs work tickets, run once every launch rather than once per schema bump.

Preparing a downloaded episode is automatic and runs in one worker process, `Producer/Workers/wilted_pipeline.py`: transcript first (the feed's published transcript, else local speech-to-text aligned to the audio, else the episode page's prose), then ad detection and an ffmpeg cut, then the cues are remapped onto the cut audio so the transcript follows playback. A published transcript is used only when it describes the file that was actually downloaded: hosts insert advertising at request time, so the same episode is served at different lengths, and timing taken from a shorter rendering drifts the reading position and points the cut at conversation. The worker compares the transcript's last cue against the audio's probed duration, records the measurement on every run, and falls through to speech-to-text when the audio is longer by more than 45 seconds or half a percent. That comparison governs transcript-only preparation. It decides nothing on a removal run: when ad removal is asked for, the publisher's transcript is not fetched or parsed at all, and one aligned `parakeet-tdt-1.1b` pass is both the detector's input and the transcript that is displayed. A destructive cut requires that aligned pass and nothing else -- a request that forbids local speech-to-text while asking for ad removal is refused before any model work, and timing that is not finite, not in order, or does not fit the downloaded audio within a declared three-second tail is refused rather than repaired, because quietly repairing it would aim real cuts using timing nothing has vouched for. The aligned speech-to-text result is cached atomically by immutable audio revision, validated before reuse, refreshed on access, and bounded to 32 entries, so a detector retry does not transcribe unchanged audio again. The worker is Python because the tuned `wilted.ads` detector and its supporting package are project-owned under `Producer/Runtime/src`; the generated interpreter lives under `Producer/Runtime/.venv`, and no archive path is part of the active runtime; `WILTED_PIPELINE_PYTHON`, `WILTED_PIPELINE_WORKER`, `WILTED_PIPELINE_PYTHONPATH`, `WILTED_PIPELINE_TIMEOUT_S`, and `WILTED_PIPELINE_TOOL_PATH` override the locations. It needs the repaired Gemma GGUF under `~/models/gemma-4-repaired` and `ffmpeg`/`ffprobe` reachable from the worker's PATH, which the app extends with `/opt/homebrew/bin` and `/usr/local/bin` because a Finder launch inherits neither. The worker checks both before spending minutes on speech-to-text, acquires the canonical GPU lock with live progress, verifies zero daemon residency and no other admitted work while holding it, releases and drains before retrying when needed, and retains the lock through ad-model close. Waiting for that lock and talking to the daemon behind it have separate budgets: waiting on a peer that legitimately holds the GPU is allowed to take as long as that peer's work, while each daemon call after the lock is held keeps a ten-second bound so a daemon that has stopped answering still fails visibly. One shared budget covered both, and three episodes downloaded at once cost two whole preparations to it. The app also admits one preparation at a time and queues the rest, because two concurrent runs do not share the GPU, they evict each other's resident speech models and retry; a waiting episode reads Queued rather than Preparing. The worker reports a detector whose model never answered as a failed preparation rather than as an episode with no advertisements, and relays warnings into the preparation journal. A run says exactly one of three things about advertising -- `disabled`, `noAds`, or `cut` -- and everything else is a typed failure that preserves the previous audio: no timed input, an unloadable model, a classification the model never resolved, an unsafe or empty keep map, a render that failed or wedged, and a rendered file whose measured duration disagrees with the map that produced it by more than 0.35 seconds. `noAds` and `cut` are refused by the app unless the worker also sends the detector's audit: how many requests it made, how many failed, which segment identifiers went unresolved. A detector that examined every window and found nothing and a detector that never reached the model both look like an episode with no advertisements, and only the audit separates them. The cut is re-encoded accurately rather than stream-copied, and what the run reports as removed is the exact complement of the map the renderer was given, not the spans the detector proposed; the proposals ride along separately as review material. Bounded explicit-anchor recovery pairs a host-read call to action with a second signal and verifies the return-to-content boundary, so a read the coarse pass took for conversation is still cut. The second signal is an address (spoken or written, with a top-level domain list that reaches past the 2005 seven, plus a platform path such as "patreon slash …" and an offer code) or, failing that, the sponsor's own name coming back at least three times within ninety seconds of the anchor. Recurrence is there because the detector reads an unpunctuated transcript: Giant Bombcast 955 sends listeners to videogame.town, which arrives as three ordinary words with no dot in them, and its ninety-second read was skipped for having no address while naming its sponsor thirteen times. The call to action stays mandatory, and recurrence only counts while it is dense, because a ten-minute window is long enough for a topic to be named that often honestly. A produced spot carries none of that evidence — nobody on the show reads it, and a promotion for another podcast sells no product at all — so both edges of the file are reviewed separately. The opening review asks one bounded question about where the program begins and a second, handed only the passage the first nominated, that withdraws the span if it finds the hosts inside it. The closing review is the same pair mirrored: where has the program finished, and is any of the appended passage still the show. Both cut to the program's edge rather than to the last advertising cue, because the gap between them is the spot's own music bed, and the closing cut runs to the end of the file for the same reason. A closing confirmation that finds the sign-off inside what the first question nominated narrows the ending once and asks again; a second disagreement ends the review. Because a cut lands on a segment edge, a segment holding an advertisement's last words and the program's first words is settled by its own bounded question, asked about that one segment: TechCrunch Daily's tenth segment carries five seconds of a Plaud call to action and then the episode title and the first story, and cutting past it would have taken the show's opening out of the file. That question outranks the confirmation when the two disagree about the boundary segment alone, which is what recovers a closing cross-promotion whole instead of in thirds. At the closing edge the question is not asked when two seconds or more of silence separate the nominated segment from the one before it: speech-to-text splits at a pause that long, so that segment cannot also hold the sign-off's last words. A TechCrunch Daily cross-promotion starting 5.6 seconds after the sign-off was otherwise judged to be the show and its first 20 seconds played. A detected span is measured against the episode before anything is cut: one span covering more than half the audio, or a set of them covering more than 60% of it, is a detection failure rather than advertising and is dropped with `ads.detect.span.rejected` or `ads.detect.refused` naming the share. The archived detector brackets an ad that goes out and comes back as one pod, bounded at ten minutes and 128 segments, which on a nine-minute show reaches across the whole programme — a TechCrunch Daily episode came back 1:52 of 9:23 with the news between its two real host reads gone. Before it is dropped, an oversized span gets one bounded resize review in the same two-question shape as the opening: where does the program resume inside this span, and, handed only the shortened passage, is any of it program after all. A shortened span that is still implausibly large, or one the second question finds the hosts inside, is refused and falls through to the rejection, so the review can recover advertising but never widen a cut. On the TechCrunch Daily episode it returns the real 0:07-3:07 read and hands the news back. What it declines to shorten is dropped rather than trimmed, because nothing at that point knows where the advertisement ended, and uncut audio is recoverable where over-cut audio is not: preparation writes over the download. Only the front of a span is recovered; a true bracket keeps its closing read in the audio. A completed terminal journal entry preserves validated, bounded removed and kept intervals, allowing Prep to show every original cut at its prepared-file seam after relaunch. Prep keeps each run's narrative above one action row and exposes its selectable monospaced event log in a bounded scroll region. Retry always starts work or reports why the source is unavailable; cancellation finishes only after cleanup. Redoing a good preparation ("Prepare this copy again") and fetching the publisher's file again ("Download again, then prepare") are both in the Larder row's … menu on any downloaded episode, under a line saying that preparing writes the cut audio over the download. That is why the fetch exists: a run that cut the wrong seconds has consumed the only copy of its own source, so re-preparing alone cannot undo it, and the labels name which file each route starts from. A run the journal still calls live when the app launches was interrupted with its process, since every run belongs to the process that started it; bootstrap closes it as failed with the reason, and Prep offers the retry.

The feed's show notes are stored with each episode (store version 9; `description`, `content:encoded`, or `itunes:summary`, whichever is longest, reduced from HTML to plain text with each link's address kept in parentheses, capped at 32 KiB) and shown three ways: the Larder row leads with the notes' opening paragraph instead of the author, the row's title opens the whole of them in a popover, and Now Playing has a Notes pane beside Transcript. Every address is clickable in both readings. The title underlines itself under the pointer rather than colouring every row in the list, and a row whose feed published no notes is plain text with nothing to press. They also ride in the worker request as `episodeNotes`, where they become a glossary: the hosts, guests, products, and sponsor sites the notes spell out are applied to the transcript after the cut, exact lower-case hits taking the notes' casing and near-misses ("sama boul samad", "adaptive security dot com") taking the spelling when the letters are at least 80% alike and the target is not an ordinary word. One `parakeet-tdt-1.1b` pass supplies aligned cues for both ad detection and playback timing on every removal run, and on a transcript-only run whose feed published nothing usable. Segments are put in time order before anything reads them: transcription runs in 120-second GPU windows with 15 seconds of overlap, and stitching them emits a few segments that start before the one ahead of them (four in 1028 on a two-hour episode, every one at a window seam). The display cues never showed it because they are sorted on projection, but the detector is handed the list unsorted and reads it by position, and the aligned cache refused to save every episode it was ever offered.

Larder episode rows show active and failed preparation states, plus a completed `Ready`, transcript, and ad-removal summary only when the successful terminal journal matches the audio revision currently ready to play. Prep retains the full recorded run.

The Larder projection (`loadLibrary`) reads one `podcastLibrarySnapshot()` per refresh rather than assembling itself from a store call per article and per episode: every table it needs -- articles, episodes, feeds, subscriptions, downloads, ready revisions, playback, transcripts, preparation outcomes, listening state, retirement, and the full preparation run history -- is fetched exactly once and handed back as indexed dictionaries, so a refresh costs the same regardless of library size. Preparation run evidence in the snapshot is uncapped: Prep's own `preparationRuns()` still caps its display list at 200 recent runs, but Larder needs every subscribed episode's evidence, capped or not, so it reads the same uncapped history the snapshot already fetched instead of asking the store to bypass its own display limit.

`Producer/Runtime` owns the Python package used by podcast preparation together with its `pyproject.toml` and locked dependency graph. It defers the `macos-ui-tests` leg, which drives real HID events through WindowServer and takes over the cursor, keyboard, and window focus for its whole run. Installing also guarantees the identity: macOS resolves a click through LaunchServices, which keys on `CFBundleIdentifier` across every registered bundle rather than on a path, so the installer refuses to start while a podcast preparation is positively proven active, refuses to finish while a second bundle in the destination claims `com.zerodelta.wilted.mac`, unregisters every stale record for that identifier -- gate and capture runs register from temp roots they then delete -- and asserts the identifier resolves to the bundle it just wrote. `tests/test-install-mac-app.sh` covers those guards hermetically. Mac UI execution requires an installed Apple Development identity for the configured `WILTED_DEVELOPMENT_TEAM` and fails closed before launch if the host or runner identity differs. XcodeGen `project.yml` remains authoritative and generated project output is absent/ignored. Ad-removal quality is measured against hand-labelled real episodes rather than against synthetic tests of the detector's own logic: `make ad-corpus` scores the cuts each preparation already committed to the library, needs no model, and answers whether an episode on this machine is still wrong, while `make ad-corpus-replay` re-runs the live detector over the aligned segments the original run consumed so a candidate fix is measurable before anything is re-prepared. `Producer/Workers/adcorpus/manifest.json` carries the labels -- `must-cut`, `must-keep`, and `acceptable-cut` for content that is not advertising but that the owner has said he does not mind losing -- and scoring is deliberately asymmetric, since leaving an advertisement in is an annoyance and removing programme content destroys something the cut file cannot give back. The replay is strict -- a case whose cached transcript is missing fails the run rather than skipping, because a candidate judged on a subset of the corpus is how a bad fix gets called good -- while the recorded mode stays lenient so a machine that has prepared neither episode can still read the report. Scoring unions the produced cuts before measuring them, judges an advertisement by the seconds left of it rather than by a coverage fraction, bounds programme loss across the whole episode as well as per span, and reports how much of each run fell outside any label so a verdict says how much of it was actually measured. Each reported detector failure is expected to enter the corpus before its fix is written; where the input or the labels no longer exist, the manifest's `gaps` array records the specific gap instead of inventing a case. The corpus holds three hand-labelled episodes, all of them tuning inputs, so passing it is not evidence of general reliability. ## Host-read recovery

Host-read recovery no longer depends entirely on a known sponsor-opening phrase. Adjacent call-to-action and destination evidence, including phrases split across cue boundaries, can nominate a bounded envelope; one constrained review selects a contiguous commercial subset containing that evidence, and an independent proposal-focused programme review sees every character of the proposed cut, labels each proposed cue and two cues either side as commercial, programme, or mixed, vetoes any programme or mixed cue, and requires programme on both sides. A proposal that is only the first spot of a longer pod has commercial cues beside it, so the review labels up to three more pairs outward on that side before declining; the pod continuation then extends the cut to the programme. Asking the model to list which proposed cues were programme had it list all of them, and a Planet Money pod of three spots played. A candidate whose complete text cannot fit the review budget is preserved rather than reviewed from a truncated excerpt. Explicit recovery verifies every cue from its anchor through its commercial evidence, including at transcript start, so CTA and destination signals cannot accumulate across intervening editorial speech; a consecutive opening pair separately requires its dedicated prefix proof. An episode-wide extra-call cap, duration/share bounds, overlap rejection, and fail-closed parsing limit the unanchored path; reads with neither an explicit opening nor CTA/destination evidence remain outside it.

Oversized candidate ad spans receive a bounded programme review. A full-span cut needs an explicit advertising-throughout answer; a mixed span can retain only a separately confirmed prefix before the first programme cue. Programme evidence never lets a later advertising-evidence rescan approve the original full span. The labelled ad corpus replay is the acceptance check for detector quality; a safe refusal can still leave sponsor audio and must be reported as a failed case.

## Conventions

- A reported ad-detection failure becomes a corpus case before it becomes a fix; the corpus stores labels and pointers, never episode audio or transcript text.
- User-visible UX changes start as a standalone interactive HTML mockup under `docs/mockups/`. Iterate there until the owner accepts the states, wording, and interaction model; only then translate the accepted mockup into native SwiftUI and its automated coverage. A mockup is design evidence, never implementation or acceptance of the built app.
- Keep all Wilted-owned project files self-contained under this directory. The preparation runtime may use only its documented shared `~/Documents/Projects/speech-stack` prerequisite; the reference-only archive is not an active dependency.
- Secrets belong in BWS and never in committed files.
- UI code does not write producer state directly; shared domain contracts own identity, transfer, and playback reconciliation.
- Native UI follows the canonical Zero Delta structure with Wilted's restrained lettuce identity; use literal navigation labels and reserve semantic colors for state.
- Where an SF Symbol clearly stands for a one- or two-word status or action (play, skip, remove, download, retry, played, in progress), the icon is the default: icon-only, with the word kept as its tooltip (`.help`) and in its accessibility label. Phrases, counts, and anything without an unambiguous symbol stay text.
- Wilted's own symbols live in `Shared/WiltedSymbols.xcassets` as SF Symbols variable templates (exported from the SF Symbols app; both targets compile the catalog) and are named through `WiltedSymbol` in `Shared/WiltedSymbols.swift`: the larder for the Larder, the cutting board for Prep, the food processor for a preparation in progress, lettuce for an article, cabbage for an episode, broccoli for a feed. `Image(symbol:)` and `Label(_:symbol:)` take either a `wilted.` name or a system name, so a `symbolName` string can be either. A symbol added to the catalog must be added to the enum; `testCustomSymbolsResolveFromTheCatalog` in both unit targets fails on a name the bundle cannot resolve.

- `LocalLibraryStore`'s SwiftData schema is versioned (`LocalLibrarySchemaVersion`, currently V10) and every version-bumping change adds a brand-new frozen model class rather than mutating a shipped one, migrating through `LocalLibraryMigrationPlan`'s lightweight stages. V10 adds `PodcastPreparationOutcomeRecord` (revision-scoped preparation eligibility/provenance), `PodcastListeningRecord` (item-scoped listening completion), `PodcastEpisodeRecord.retiredAt`, and `PodcastDownloadRecord.failureKind`. An idempotent `reconcilePodcastStateV10()` backfills preparation outcomes and listening records from pre-V10 durable state (journal entries, `PlaybackRecord`s, and legacy invalidation markers); `WiltedMacModel.performStoreBootstrap()` calls it on every launch, before `invalidateStalePodcastPreparations`, so a store owner does not call it explicitly. `retiredAt` and `failureKind` have no pre-V10 history to backfill and simply start `nil`. See `INVARIANTS.md` W-INV-011.
- `PodcastPreparationPipeline`'s `semanticFingerprint` (`semanticVersion` + `workerSourceHash` + `pipelineSourceHash` + the resolved Python dependency hashes) identifies which pipeline version produced a stored preparation outcome, but a fingerprint mismatch on its own invalidates nothing: `invalidateStalePodcastPreparations` only acts on episodes an explicit `PodcastPreparationInvalidationRule` in `PodcastPreparationPipeline.invalidationRules` matches, and that table starts empty. Add a rule only when a specific pipeline change actually made prior output wrong; an unrelated refactor, comment, or logging change should never force a redownload or re-preparation. `pipelineSourceHash` covers `PodcastPreparationPipeline.swift` itself (with its own line normalized out), so any edit to that file — including adding a rule — fails `semanticFingerprintCoverageRequiresTheWorkerAndSwiftSourcesToBeBumped` until the hash is recomputed and updated; this is deliberate, forcing a conscious decision about whether the edit is semantic. `WiltedMacModel` takes its rule table via an `invalidationRules` init parameter defaulting to the production table, so tests can inject a scenario-specific rule without changing what ships. A rule's `.forceRedownload` consequence is admitted one at a time through a detached bootstrap-recovery task (not inline in `performStoreBootstrap()`), so a library-wide migration with many stale episodes cannot open N simultaneous transfers and cannot hold the app in a non-ready state for the whole recovery burst; `waitForPodcastOperations()` is the test seam that waits for that task to drain.

- Every podcast download, podcast preparation, and article preparation request is durable: `LocalLibraryStore` keeps one `WorkTicket` row per `(kind, subjectID)`, moving through `pending`/`deferred` (admitted, not yet running) → `running` → a terminal state (`succeeded`/`failed`/`cancelled`). `WorkTicketState.canTransition(to:)` only allows forward movement within one request sequence; `readmitWorkTicket` atomically replaces a settled attempt’s policy and stale failure/run fields for a newer sequence, while late older writes are ignored and duplicate running writes count only once. `applyWorkTicketTransition` does the whole find/validate/mutate/save as one actor-isolated call with no `await` in the middle -- the actor itself is what serializes two Tasks racing to transition the same subject, given a conflicting insert on `@Attribute(.unique)` measurably throws on neither side and would otherwise lose a write silently. An article's `subjectID` is `ItemID.derive(from:)` the pasted draft URL -- pure and networkless, so it is stable at request time -- and its `resolvedItemID` is stamped once extraction returns the canonical URL, which a draft link and the canonical article it redirects to can disagree on. `reconcileWorkTickets(in:)` runs on every launch, before the library loads: it imports preferences-held off-peak deferrals and orphaned podcast downloads as tickets, closes any ticket left `running` by a process that is not this one (retried as `pending`, or failed once its attempt budget is spent), collapses an article-preparation duplicate that another draft URL's ticket already resolved to the same `resolvedItemID` (keeping the most recently requested, cancelling the rest), and prunes terminal tickets older than 30 days while always keeping at least the newest 50 per kind. A ticket-drain ticker (`startTicketDrainTicker`, distinct from `startAutomationTicker`) evaluates admission for whatever non-terminal tickets exist on a fixed interval and, unlike the open-window tick, keeps running while the window is hidden -- `checkpointForBackground` never stops it, only actual termination does -- because an off-peak window opening behind a hidden window used to go unnoticed until the window came back.
