## Git hooks

Install the repository-owned hooks once per clone:

```bash
make install-hooks
```

The `pre-commit` hook runs `make check-fast`: commits warn above 500 lines and fail
above 800 unless `.file-size-exceptions` lists the file with a reason. It checks staged
`.swift`, `.py`, and `.sh` files through `scripts/check_file_size.py`; `make validate` audits
the whole tree. The `pre-push` hook runs `make validate` and nothing else, so a push
never waits on the screen-seizing Mac UI run. The
installer is idempotent and sets the installing worktree's private
`core.hooksPath` to its `.githooks`, so installing in one linked worktree does
not change its siblings. A legacy shared `.githooks` setting is migrated only
when this is the sole worktree; with linked siblings, installation refuses
without changing Git configuration.

Run `make worktree-setup` once in each new linked worktree (`.claude/worktrees/*`,
a Codex worktree) before its gates. The runtime lock and the release wrappers
resolve the `speech-stack` and `apple_developer` projects beside the checkout, so
the target links each one beside the worktree to the main checkout's sibling,
syncs `Producer/Runtime/.venv` from `uv.lock`, and fails unless the speech
stack's GPU lock resolves to the shared `~/Documents/Projects/speech-stack/.state`.
It is idempotent and never replaces an existing entry that resolves elsewhere.

## Test tiers

1. **Commit:** `make check-fast` (lint, dead code, file size, scratch).
2. **Push:** `make validate`, the headless gate. It defers the `macos-ui-tests` leg and says so. A failing step never stops it: every step runs, and the run ends with one `validate.failed count=<n> steps=<names>` line.
3. **Install:** `make install` runs `scripts/verify-once-gate.sh check-ui` and refuses unless every `ui` leg of the adapter (`macos-ui-tests`) has a fresh verify-once receipt for the exact source of the tree being installed (any edit to a source input makes it stale). `WILTED_SKIP_UI_RECEIPT=1 make install` proceeds anyway and prints a warning; use it only when the Mac UI leg cannot run. `make install-walkthrough` is the release walkthrough's install: it runs `make validate` and installs only if that passes, with no UI receipt, because the screen-seizing leg runs once after the walkthrough, on the final candidate.
4. **`make native-ui`** (or `app/verify-release-ui`): runs only the screen-seizing XCUITest leg through the same verify-once layer and records its receipt. Run it when away from the Mac.

**Verify once.** `scripts/verify-once-gate.sh` runs each `scripts/test-gate.sh` leg through the `apple_developer` receipt layer (legs declared as `gateLegs` in `.release/release-adapter.json`). A headless leg whose input files, toolchain and simulator runtime match a fresh receipt from any worktree is reused (`gate-leg <id>: reused`); a passing leg records a receipt in `<git common dir>/release-receipts/wilted-ios/<leg>/`. `make validate` and the release local gate (`app/release_local_gate.sh`) share these receipts. A narrowed run (`WILTED_GATE_LEGS` and the other selectors) never records one. `app/release-testflight` and `app/release-status` re-exec inside a tool-owned release checkout; run `make worktree-setup` in a new worktree first (it also links the sibling `speech-stack`).

**Single-leg reruns.** `WILTED_GATE_LEGS=<comma list>` runs only the named legs of `scripts/test-gate.sh` (`xcodegen-reproducible`, `wiltedkit-tests`, `cloudsync-tests`, `playback-tests`, `wiltedproducer-tests`, `macos-unit-tests`, `ios-unit-tests`, `macos-ui-tests`, `ios-pixel-snapshot-tests`), for example `WILTED_GATE_LEGS=wiltedkit-tests bash scripts/test-gate.sh`. Unknown, empty or malformed names fail closed before any leg or simulator sweep runs. The summary still prints `native.complete`, lists the skipped legs on `native.leg.skipped` and `native.filtered` lines, and qualifies the pass line as `native.passed count=<n> filtered=<k>`. A filtered run is a diagnostic only: the verify-once layer records no receipt while the variable is set. `tests/test-native-gate-legs.sh` holds the meta-tests. The opt-in `watchos-build` leg hosts `WiltedWatchTests` on the persistent owned 45 mm watchOS simulator and shuts down only the simulator it booted. It writes four named shared-shipping-content PNGs under `.logs/watch-captures/<base-sha>/working-tree-*/`, labelled uncommitted when appropriate; native containers and navigation are excluded. Speed and Sleep capture their full content at the actual 45 mm width and intrinsic height. This is not a full-screen, native-layout, or owner-acceptance receipt. The default gate is unchanged: name `WILTED_GATE_LEGS=watchos-build` in a separate gate run, not around `make validate`, whose phase-0 meta-tests would inherit the filter.

**Single-test reruns.** `make native-mac-unit TEST=<Class[/testMethod],...> [ITERATIONS=<n>]` runs one XCTest class or method of `WiltedMacTests`, N times, through the gate's own build, signing, lock and temp-ownership path; `make native-ios-unit` does the same for `WiltediOSTests` through the same simulator session and `apple-ui-test-lock` lane as the full iOS leg. For example `make native-mac-unit TEST=BulletinProducerTests/testAnUnchangedListIsNotRepublished ITERATIONS=5`. The targets set `WILTED_GATE_LEGS` to the one unit leg (which brings `xcodegen-reproducible`) plus `WILTED_MAC_UNIT_SELECTORS` and `WILTED_MAC_UNIT_ITERATIONS`, or `WILTED_IOS_UNIT_SELECTORS` and `WILTED_IOS_UNIT_ITERATIONS`; the variables also work directly with `bash scripts/test-gate.sh`. A selector is a comma list of `Class` or `Class/testMethod` (the gate adds the target name), and iterations are 1 to 100, passed to `xcodebuild -test-iterations`. An empty, malformed or metacharacter-bearing value fails closed before any leg starts. A Mac selector lowers that leg's test-count floor from 30 to 1, so a misspelled class fails as `native.zero-tests` instead of passing an empty run. Any of the four variables makes the run a filtered diagnostic: the summary adds `native.filtered.tests leg=<leg> selectors=<list|all> iterations=<n> receipt=never`, and the pass line always carries `filtered=<k>`, so no receipt can be minted from it. `make validate` unsets all four. Many iterations can outrun the leg's budget: the Mac unit leg builds and tests under one 1,200-second budget (`WILTED_XCODE_BUILD_AND_TEST_TIMEOUT_SECONDS`), while the iOS legs build first under the 1,800-second build budget and then test under the 600-second test budget (`WILTED_XCODE_TEST_TIMEOUT_SECONDS`); raise the relevant one for a long run. To compare against a base commit that has these targets, run the same target in a detached scratch worktree (its first build is cold, because `.build` caches are per checkout):

```bash
base="$(mktemp -d "$TMPDIR/wilted-base.XXXXXX")"
git worktree add --detach "$base/wt" origin/main
make -C "$base/wt" native-mac-unit TEST=BulletinProducerTests/testAnUnchangedListIsNotRepublished ITERATIONS=5
git worktree remove "$base/wt" && rmdir "$base"
```

## Bounded tests and scratch

`make validate`, `make native-ui`, the gate scripts, and the shell test entrypoints use the repository's bounded runner (`scripts/run-bounded.py`) to clean up each command's observed child processes, including descendants that leave the original process group. Ordinary shell test entrypoints default to a 1,800-second work budget and individual build commands to 300 seconds; `WILTED_TEST_RUNNER_TIMEOUT_SECONDS` and `WILTED_TEST_TIMEOUT_SECONDS` override those budgets. Gate orchestrators instead wait with visible heartbeats and no default aggregate wall-clock deadline: dependency, cache-lock, simulator-readiness, and shared-destination waits do not consume a leg's work budget. Native builds default to 1,800 seconds and test work to 600 seconds, starting only after their required lock and readiness steps. Native Xcode legs use `build-for-testing` followed by `test-without-building`, retaining per-leg DerivedData; shared test destinations serialize while independent builds proceed. `scripts/build-with-cache.py` reuses the checkout's shared `.build` caches, and lock waits are heartbeat-only unless a diagnostic lock timeout is explicitly set. The five test targets in `Producer/Runtime/Makefile` (`test`, `test-unit`, `test-integration`, `test-e2e`, and `test-tui`) run pytest through the same supervisor. Cancellation and timeout cleanup stop and reap owned descendants before releasing owned state. A timeout or cleanup failure is nonzero, and a deferred native UI leg is still a deferral, not a pass.

Create ephemeral Wilted scratch below the inherited `$TMPDIR` with a unique `mktemp -d` path, register cleanup before starting child work, stop/reap owned children, and preserve only cited evidence under `.logs/`. The native and Phase 0 gates remove their own scratch on normal exit and handled signals; before starting, they sweep only root-level `wilted-*` entries at least 24 hours old with an explicit ownership marker, an inactive owner, and no holders, while historical unmarked or borrowed spec directories are preserved. The active-tree check `scripts/check-no-global-tmp.py` rejects hard-coded absolute global temporary-root references in operational scripts and documentation. Captain and worker procedures are recorded in the internal plan overlay and bounded-task template; those templates require caller-shell cleanup and reuse of shared `.build` caches.

## Scope

Larder is the one place kept episodes wait. The active podcast appears in Now Playing instead of a second Ready row; the durable queue retains its position for playback succession. Larder groups waiting episodes as Ready, Needs preparation, and Not downloaded, and shows a completed preparation summary only when a successful terminal journal matches the audio revision currently ready to play. A transcript by itself or a journal for an older revision is not presented as prepared. Ready-media reconciliation and export use the publication snapshot to omit unrelated transcript and preparation-history decoding while retaining exact prepared-media proof.

The active milestone turns the native SwiftUI Mac app into a daily driver. The existing article path stays intact; the milestone adds subscribed feeds, cancellable local episode downloads with visible progress, atomic enclosure imports, a durable Larder listening queue, continuous playback, direct seeking, persistent speed, and exact resume. Feeds, episodes, queue state, playback speed, and episode checkpoints remain local-only until Phase 3 Mac owner acceptance. The existing iOS listener and article CloudKit path remain unchanged while that Mac milestone is implemented and qualified.

Navigation is a destination switch on both platforms. The Mac sidebar lists Larder, Feeds, and Settings, in that order, followed by a Playlists section (manual playlists filled with Add to Playlist from a Larder row, and automatic playlists built from rules; playing one never changes the Larder order, W-INV-028); a toolbar button or Control-Command-S hides and shows it, and the window restores its selection, scroll positions, Larder filter and search, and drafts at launch (View > Clear Saved View resets them). Feeds is a one-decision inbox: Keep moves an episode to Larder and Skip moves it to the collapsed Off the list section. Refresh adds metadata only, exposes live progress and Cancel, and records the last successful refresh; undecided episodes never start download or preparation. Larder owns downloading, preparing, sorting, playback, and queue order. It is one list grouped Ready, Active work, Downloaded, then Not downloaded, holding episodes, articles and books, with a kind filter (All, Podcasts, Articles, Audiobooks); book rows and both players show the current chapter with previous and next steps. Adding goes through one Add sheet (toolbar Add, or File > Add… with Command-N): paste a podcast or article link, or type a show name to search Apple Podcasts (`itunes.apple.com/search` and `/lookup`, HTTPS only, no redirects, debounced), and each result offers one action, Subscribe or Add article, with shows you already follow marked. A feed with no audio episodes is offered as an article feed: Wilted refreshes it for new posts and offers them in the Feeds inbox, and a feed with neither audio nor posts is refused. Import book (or a file drop) imports audio files or a folder as one chaptered audiobook, identified by its content (W-INV-027), or turns EPUB or PDF text into a spoken book; archive and XML input is treated as untrusted (entity declarations refused, size and entry caps). Its independent **Group by** control offers Feed, Date, and Status, while **Sort by** offers Length, Age, Alphabetical, and Custom, with a saved direction for the ordered modes; each row shows its release date. The selected sort preference persists across playback, natural continuation, and app relaunch, while explicit manual drag and drop switches back to Custom order and draws the exact insertion gap. Feeds Skip is reversible. Skipped and retired episodes remain stored and appear under Feeds' collapsed **Off the list** section, where Restore clears the stored removal without a feed fetch or rematch. Manual-completion recovery replays admission only for feeds named by completion receipts; a receipt-free startup does not trigger unrelated admission.

Preparing a downloaded episode is automatic and runs in one worker process, `Producer/Workers/wilted_pipeline.py`: transcript first (the feed's published transcript, else local speech-to-text aligned to the audio), then ad detection and an ffmpeg cut, then the cues are remapped onto the cut audio so the transcript follows playback. A published transcript is used only when it describes the file that was actually downloaded: hosts insert advertising at request time, so the same episode is served at different lengths, and timing taken from a shorter rendering drifts the reading position and points the cut at conversation. The worker compares the transcript's last cue against the audio's probed duration, records the measurement on every run, and falls through to speech-to-text when the audio is longer by more than 45 seconds or half a percent. That comparison governs transcript-only preparation. It decides nothing on a removal run: when ad removal is asked for, the publisher's transcript is not fetched or parsed at all, and one aligned `parakeet-tdt-0.6b-v3` pass is both the detector's input and the transcript that is displayed. A destructive cut requires that aligned pass and nothing else -- a request that forbids local speech-to-text while asking for ad removal is refused before any model work, and timing that is not finite, not in order, or does not fit the downloaded audio within a declared three-second tail is refused rather than repaired, because quietly repairing it would aim real cuts using timing nothing has vouched for. The aligned speech-to-text result is cached atomically by immutable audio revision, validated before reuse, refreshed on access, and bounded to 32 entries, so a detector retry does not transcribe unchanged audio again. The worker is Python because the tuned `wilted.ads` detector and its supporting package are project-owned under `Producer/Runtime/src`; the generated interpreter lives under `Producer/Runtime/.venv`, and no archive path is part of the active runtime; `WILTED_PIPELINE_PYTHON`, `WILTED_PIPELINE_WORKER`, `WILTED_PIPELINE_PYTHONPATH`, `WILTED_PIPELINE_TIMEOUT_S`, and `WILTED_PIPELINE_TOOL_PATH` override the locations. It needs the repaired Gemma GGUF under `~/models/gemma-4-repaired` and `ffmpeg`/`ffprobe` reachable from the worker's PATH, which the app extends with `/opt/homebrew/bin` and `/usr/local/bin` because a Finder launch inherits neither. The worker checks cut tools before speech-to-text, then checks model availability after the aligned transcript exists; a missing ad model can therefore return usable cues and the documented uncertain result with original audio. It then acquires the canonical GPU lock with live progress, verifies zero daemon residency and no other admitted work while holding it, releases and drains before retrying when needed, and retains the lock through ad-model close. Waiting for that lock and talking to the daemon behind it have separate budgets: waiting on a peer that legitimately holds the GPU is allowed to take as long as that peer's work, while each daemon call after the lock is held keeps a ten-second bound so a daemon that has stopped answering still fails visibly. One shared budget covered both, and three episodes downloaded at once cost two whole preparations to it. The app also admits one preparation at a time and queues the rest, because two concurrent runs do not share the GPU, they evict each other's resident speech models and retry; a waiting episode reads Queued rather than Preparing. An unresolved ad review is reported as `uncertain`: the worker returns the proven original audio unchanged and sends a warning plus actual request, failure, and unresolved-segment counts, which the app validates and stores in the durable preparation journal. That original audio remains playable. Genuine missing or invalid audio, render failures, and invalid proof remain typed failures that preserve the previous audio. Other outcomes are `disabled`, `noAds`, and `cut`; the app requires detector audit evidence for completed detection, so a detector that examined every window and found nothing cannot be confused with one that never reached the model. A successful cut also requires a safe nonempty keep map and a rendered duration within 0.35 seconds of the map's prediction. The cut is re-encoded accurately rather than stream-copied, and what the run reports as removed is the exact complement of the map the renderer was given, not the spans the detector proposed; the proposals ride along separately as review material. Bounded explicit-anchor recovery pairs a host-read call to action with a second signal and verifies the return-to-content boundary, so a read the coarse pass took for conversation is still cut. The second signal is an address (spoken or written, with a top-level domain list that reaches past the 2005 seven, plus a platform path such as "patreon slash …" and an offer code) or, failing that, the sponsor's own name coming back at least three times within ninety seconds of the anchor. Recurrence is there because the detector reads an unpunctuated transcript: Giant Bombcast 955 sends listeners to videogame.town, which arrives as three ordinary words with no dot in them, and its ninety-second read was skipped for having no address while naming its sponsor thirteen times. The call to action stays mandatory, and recurrence only counts while it is dense, because a ten-minute window is long enough for a topic to be named that often honestly. A produced spot carries none of that evidence — nobody on the show reads it, and a promotion for another podcast sells no product at all — so both edges of the file are reviewed separately. The opening review asks one bounded question about where the program begins and a second, handed only the passage the first nominated, that withdraws the span if it finds the hosts inside it. The closing review is the same pair mirrored: where has the program finished, and is any of the appended passage still the show. Both cut to the program's edge rather than to the last advertising cue, because the gap between them is the spot's own music bed, and the closing cut runs to the end of the file for the same reason. A closing confirmation that finds the sign-off inside what the first question nominated narrows the ending once and asks again; a second disagreement ends the review. Because a cut lands on a segment edge, a segment holding an advertisement's last words and the program's first words is settled by its own bounded question, asked about that one segment: TechCrunch Daily's tenth segment carries five seconds of a Plaud call to action and then the episode title and the first story, and cutting past it would have taken the show's opening out of the file. That question outranks the confirmation when the two disagree about the boundary segment alone, which is what recovers a closing cross-promotion whole instead of in thirds. At the closing edge the question is not asked when two seconds or more of silence separate the nominated segment from the one before it: speech-to-text splits at a pause that long, so that segment cannot also hold the sign-off's last words. A TechCrunch Daily cross-promotion starting 5.6 seconds after the sign-off was otherwise judged to be the show and its first 20 seconds played. A detected span is measured against the episode before anything is cut: one span covering more than half the audio, or a set of them covering more than 60% of it, is a detection failure rather than advertising and is dropped with `ads.detect.span.rejected` or `ads.detect.refused` naming the share. The archived detector brackets an ad that goes out and comes back as one pod, bounded at ten minutes and 128 segments, which on a nine-minute show reaches across the whole programme — a TechCrunch Daily episode came back 1:52 of 9:23 with the news between its two real host reads gone. Before it is dropped, an oversized span gets one bounded resize review in the same two-question shape as the opening: where does the program resume inside this span, and, handed only the shortened passage, is any of it program after all. A shortened span that is still implausibly large, or one the second question finds the hosts inside, is refused and falls through to the rejection, so the review can recover advertising but never widen a cut. On the TechCrunch Daily episode it returns the real 0:07-3:07 read and hands the news back. What it declines to shorten is dropped rather than trimmed, because nothing at that point knows where the advertisement ended, and uncut audio is recoverable where over-cut audio is not: preparation writes over the download. Only the front of a span is recovered; a true bracket keeps its closing read in the audio. A completed terminal journal entry preserves validated, bounded removed and kept intervals, allowing Prep to show every original cut at its prepared-file seam after relaunch. Prep keeps each run's narrative above one action row and exposes its selectable monospaced event log in a bounded scroll region. Retry always starts work or reports why the source is unavailable; cancellation finishes only after cleanup. Redoing a good preparation ("Prepare this copy again") and fetching the publisher's file again ("Download again, then prepare") are both in the Larder row's … menu on any downloaded episode, under a line saying that preparing writes the cut audio over the download. That is why the fetch exists: a run that cut the wrong seconds has consumed the only copy of its own source, so re-preparing alone cannot undo it, and the labels name which file each route starts from. A run the journal still calls live when the app launches was interrupted with its process, since every run belongs to the process that started it; bootstrap closes it as failed with the reason, and Prep offers the retry.

The feed's show notes are stored with each episode (store version 9; `description`, `content:encoded`, or `itunes:summary`, whichever is longest, reduced from HTML to plain text with each link's address kept in parentheses, capped at 32 KiB) and shown three ways: the Larder row leads with the notes' opening paragraph instead of the author, the row's title opens an episode information popover whose **Notes** are shown by default, and Now Playing has a Notes pane beside Transcript. That popover also offers a **Transcript** tab with the episode's already-saved transcript text, including a retired or already-played episode while its text is retained, a neutral line when nothing is saved, and a Retry action when the read fails. The same episode-name popover works from Larder, Feeds, History (Off the list and feed details), the rules preview, Playlists, and the player pane and rail, while articles keep ordinary titles. Opening it prepares no transcript and leaves Now Playing's transcript and playback independent, and dismissing or unsubscribing still deletes transcripts as before. iPhone parity is follow-up. Every address is clickable in both readings. The title underlines itself under the pointer rather than colouring every row in the list, and a row whose feed published no notes is plain text with nothing to press. They also ride in the worker request as `episodeNotes`, where they become a glossary: the hosts, guests, products, and sponsor sites the notes spell out are applied to the transcript after the cut, exact lower-case hits taking the notes' casing and near-misses ("sama boul samad", "adaptive security dot com") taking the spelling when the letters are at least 80% alike and the target is not an ordinary word. One `parakeet-tdt-0.6b-v3` pass supplies aligned cues for both ad detection and playback timing on every removal run, and on a transcript-only run whose feed published nothing usable. It writes punctuated, capitalized sentences, so the glossary's exact hits mostly confirm casing the model already chose; a segment it closes with no duration (Rogan #2565 emitted 2616.48-2616.48 "are.") is dropped before anything reads it, because the aligned cache refuses the whole pass for one. It replaced `parakeet-tdt-1.1b` under engine podcast-preparation-v13 (2026-10-27): over five fresh episodes it cut about 117 s of programme where 1.1b cut about 445 s, and left about 97 s of advertising where 1.1b left about 90 s; already prepared episodes keep their cuts. Segments are put in time order before anything reads them: transcription runs in 120-second GPU windows with 15 seconds of overlap, and stitching them emits a few segments that start before the one ahead of them (four in 1028 on a two-hour episode, every one at a window seam). The display cues never showed it because they are sorted on projection, but the detector is handed the list unsorted and reads it by position, and the aligned cache refused to save every episode it was ever offered.

Larder episode rows show active and failed preparation states, plus a completed `Ready`, transcript, and ad-removal summary only when the successful terminal journal matches the audio revision currently ready to play. Prep retains the full recorded run.

The iPhone Larder also shows the Mac’s current queued, active, failed and cancelled preparation reports before audio is available. These read-only reports include stage-local progress and a last-reported time for VoiceOver; they do not grant downloads, playback, preparation or cancellation. Available and Downloaded retain their media meaning. Associated copies retain separate reports in raw-member order, with other-copy reports identified explicitly; withdrawal or removal hides retained reports.

**Untrusted XML.** Every podcast feed, article payload, and EPUB XML file passes one linear, bounded classifier (`UntrustedXML`) before `XMLParser` exists. It decodes the payload once, refuses malformed, unsupported, or self-contradicting encodings with a typed reason, then walks the decoded bytes once: comments end at the first `-->` and processing instructions at the first `?>`, regardless of quotes; quotes hide `>` and `[` only inside tags and DOCTYPE literals; an `<!ENTITY` declaration counts only in a markup-declaration position and a DTD internal subset only outside a DOCTYPE literal. Supported encodings are UTF-8, UTF-16 (BE or LE, from a BOM or the XML byte signature), UTF-32 (BE or LE), ISO-8859-1, and windows-1252; every other spelling, an encoding that contradicts the BOM or signature, and truncated or undefined byte sequences -- including UTF-7's shifted declarations, which the old scanners missed -- are refused before parsing, while the original bytes are handed to `XMLParser` unchanged. Podcast feeds refuse every DOCTYPE; article feeds and EPUB XML keep accepting a bare DOCTYPE that carries only a public or system identifier. Both no-resolution controls are set (`shouldResolveExternalEntities = false` and `externalEntityResolvingPolicy = .never`), with the existing consumer-specific resolver behavior retained. Owned-canary tests check returned text and refusal outcomes; they do not trace resource I/O. The existing caps are unchanged and stay distinct: feed and article payloads are bounded by `PodcastFeedClient.maximumFeedBytes` (16 MiB) in the HTTPS-only loader, EPUB XML files by `BookExtractionLimits.maxXMLBytes` (8 MB), and EPUB archives by the 5,000-entry and 500 MB unpacked caps plus the 200,000-node and 200-deep XML node ceiling.

The Larder projection (`loadLibrary`) reads one full `podcastLibrarySnapshot()` per refresh rather than assembling itself from a store call per article and per episode. Its indexed read includes articles, episodes, feeds, subscriptions, downloads, ready revisions, playback, transcripts, preparation outcomes, listening state, retirement, and full preparation history. The library publisher uses the snapshot's publication profile, which omits transcript bodies and preparation-run history; download-byte updates therefore do not read those display-only payloads just to publish library state. Preparation run evidence remains uncapped in the full Larder snapshot; Prep's own `preparationRuns()` still caps its display list at 200 recent runs.

It was reference-only and non-runnable by then: absolute paths, legacy runtime bindings, an SQLite database, a shell alias, and retired launchd jobs. On 2026-08-17 the owner approved transferring the existing GitHub repository to this fresh project; the old Git history was not migrated, and the parts never ported -- its Phase-0 spikes, plans, reports, and verification records -- are gone with it. Retired nightly/hourly scheduling is disabled. The current `wilted` shell alias is stale and must not be treated as an installation.

## Python preparation runtime

`Producer/Runtime` owns the Python package used by podcast preparation together with its `pyproject.toml` and locked dependency graph. From the project root, `uv sync --project Producer/Runtime --locked` generates the ignored `Producer/Runtime/.venv`; a virtual environment is never copied or committed. The lock deliberately retains an editable dependency on the shared speech stack at `~/Documents/Projects/speech-stack`, which is an explicit host prerequisite: its source location keeps the canonical cross-process GPU lock shared. Explicitly excluded from the active Mac milestone: automatic classification, radio mode, email, social drafting, background scheduling, and TUI/CLI parity.

## Sync cadence

Each device has one 30 s sync tick (`WiltedKit` `SyncTick`, `SyncCadence.tickInterval`); every periodic read, publish, checkpoint and pending-decision check batches into its rounds and nothing runs faster. A user action sends its one write at once, a confirming read waits for the next round, a rate limit holds the whole tick for the server's Retry-After, and pull to refresh runs a round now (or shows the retry state while limited). The rule, the per-round contents, the request-rate audit and `scripts/sync-ops-rate.sh` (operations per minute from the unified log) are in `docs/2026-10-01-sync-cadence.md`; the tests that pin it are `SyncTickTests`, `LibraryPollRequestCountTests`, `WiltedMacSyncRoundTests` and `LibraryPhoneSyncTickTests`.

## Installing and the library publisher

`make install` (`scripts/install-mac-app.sh`) builds the **Development** configuration and replaces the copy in `/Applications`, quitting a running copy first. Development compiles `WILTED_CLOUDKIT_LIVE` and carries the iCloud/CloudKit and development-push entitlements, so the installed app runs the library publisher against the Development CloudKit environment by default. It signs with the Apple Development identity and the provisioning profile already cached on the Mac, never passes `-allowProvisioningUpdates` and never contacts the developer portal; a missing or expired cached profile fails the build, and refreshing it is an attended step in Xcode. Debug (unit tests) has no live transport and Release is the separate Developer ID build.

`WILTED_LIBRARY_SYNC` picks the sync engine for a launch (`WiltedMacLibraryRuntimeSelection`): unset selects the library publisher in a live Development or Release build; `1` forces it on; any other non-empty value (for example `0`) forces it off (`.none`). There is no legacy engine to return to. Test hosts, non-live builds and UI fixtures run with no sync engine (`.none`).

**Account binding.** The publisher is bound to one iCloud account owner and sends nothing until the current account is that owner (W-INV-021). An empty library binds its first owner without review. A library that has data but no binding, a sign-out, or a different account holds sending; Settings then shows why and offers a review, and approving it ("Use reviewed account") resumes sending for the reviewed account. Status text and logs carry no account identifier.

**Settings sync status.** The Sync card shows one status line for the library publisher, resolved from the account binding, the shared rate-limit throttle and local activity: waiting, working, pending, sent, idle, or a send or check failure, with a plain reason for each account hold. Times are this Mac's own send and read times; nothing on the card claims the iPhone has fetched or converged. **Sync now** runs one round, joins a round already running instead of starting another, and is not offered while an account hold or throttle applies. Relaunch account checks use the same shared throttle and preserve iCloud's requested wait; an unverified saved owner cannot admit a refresh. This is source- and fixture-tested only; the installed app and a live CloudKit account have not been exercised.

**Quit.** A normal quit (`WiltedMacTerminationCoordinator`) pauses, stops admitting work and writes the playhead, lifetime totals and in-flight download bytes within 10 s. If that fails or times out the quit is cancelled, the app stays open and offers a retry. Network work then gets only the remaining budget and a bounded join: pending cloud sends are already durable locally, so a slow cloud step never blocks or cancels a quit (W-INV-019). A forced exit or crash skips the drain and loses at most about 10 s of listening time and 1 s of download bytes.

**Store V14 (lifetime statistics).** The first launch on a build with V14 migrates the library store, adding the lifetime ledger and the played-minute, downloaded-byte and manual-skip counters. Before migrating, the store checkpoints its WAL, rehearses on a clone, verifies row counts, and keeps a backup next to the store (`<store>.v<N>-backup-<UUID>/`) that is never deleted automatically. A populated table that would be lost fails the migration and restores the original; a store newer than the build is refused untouched, so downgrading needs the pre-migration backup and loses events recorded since (W-INV-020). Procedure, restore steps and evidence: [`docs/statistics-migration-recovery.md`](docs/statistics-migration-recovery.md). Only fixture stores have been migrated.

**Playback and deletion.** Mac playback commands go through one owner where the newest explicit command wins and Play/Pause is acknowledged before the first await (W-INV-017); a pause after an episode ends holds the queue advance (W-INV-018). While moving to the next episode after you mark the current one completed, Now Playing shows the existing Wilted loading animation and “Loading next episode…”; it honors Reduce Motion and clears if the advance is cancelled or fails. Unsubscribing from a feed and removing an article ask for confirmation, a cancelled confirmation writes nothing, and a confirmed unsubscribe deletes that feed's downloaded audio once its records are saved, keeping any file another episode still names (W-INV-022, W-INV-025). A confirmed unsubscribe also reclaims feed-owned unreferenced artwork after the unsubscribe commit completes, respecting existing shared-file guards.

**Reports.** Off by default; Settings > Reports turns them on. While audio plays, a news headline from a feed marked News, or a National Weather Service alert for this device's area, is spoken at the next transcript gap (or within 60 seconds), in the voice of the device that is playing; playback is held, not paused, and resumes at the stored position, and Skip bulletin (or next track on the iPhone) cuts the speech. Each device uses its own approximate location: the Mac from Core Location with typed coordinates as the fallback, the iPhone When In Use only; never an IP lookup. Only coordinates rounded to two decimals go to `api.weather.gov`, and the User-Agent carries a contact only if you type one. The Mac can also build a morning report (forecast plus recent headlines) as a Larder item, shown under the All filter. Code: `WiltedKit/Sources/WiltedWeather/`, `WiltedMac/Reports/`, `Producer/Sources/WiltedProducer/PlaybackController+Interruptions.swift`, `WiltediOS/Library/LibraryPlayerInterruptions.swift`.

On the Mac, changing the output device or source, disconnecting a held jack or losing the output during a bulletin cuts speech and keeps the original checkpoint paused. Current output is checked again before chained speech and after restore before playback resumes. Reports shows a retryable status if output monitoring cannot be registered; closing or quitting never resumes held audio. Turning Read bulletins off normally keeps its existing resume behavior. Seeking during a Mac bulletin stops speech without playing the old checkpoint, applies the new position, then resumes after the checkpoint attempt only if playback was intended and no newer command or output-route invalidation intervened. Repeated seeks retain the pending playing intent; a checkpoint error is reported while valid playback continues at the selected position. Forward seeks retain skip accounting; backward seeks retain their new-session rewind semantics. This seek behavior is Mac-only; the iPhone seek path is unchanged.

**Feed automation.** Each feed has four automation controls on the Mac, in the feed's policy view under Feeds: **Auto keep**, **Auto download**, **Auto prepare** (each On, Off or Use global) and **Kept limit** (Use global or a count of 1 or more). A podcast feed's popover also has **Remove the show's own promotion** (off by default), which also cuts the show's sponsor roll call, ad-free or Patreon pitches, events and webinars that the detector otherwise keeps as programme; the choice is kept in the Mac's preferences (`wilted.feeds.removeSelfPromotion`), not the library, and reaches the worker as `removeSelfPromotion` in the admitted job's policy snapshot. Settings holds the global defaults that every Use global feed inherits: Auto keep (default Off), download everything (Off), prepare everything downloaded (Off) and a kept limit (none). Auto keep On is the only automatic authority to Keep a new episode; with it Off, new episodes stay undecided. Auto download and Auto prepare Off stop only automatic downloads and preparation for that feed, never a manual Prepare. When global Processing is set to Manual in Settings and Prepare everything downloaded is Off, setting Auto prepare to On displays an inline explanation that episodes will not prepare automatically until Processing or Larder settings are adjusted. An older failed save of a feed's News toggle cannot overwrite a newer optimistic choice. When a feed is full its Kept limit makes further episodes **wait for space**, oldest first, listed under Feeds with a note that Wilted never removes an existing, playing or part-heard episode to make room; completing, retiring or removing a kept episode releases the oldest waiting one, raising the limit fills open places, and lowering it removes nothing. A manual Keep or Skip, Mac dismiss, and iPhone Remove from Larder, reorder, or Restore records the owner's choice only after durable read-back, including an accepted no-op; a committed operation remains committed if that record fails, with its queue and undo follow-up intact and a warning that identifies the committed operation and unsaved choice instead of a false saved-choice confirmation; a committed Restore says it was restored but its choice could not be saved. Restore records Keep only for an episode that exists. Automation never overrides confirmed manual choices, and a manual Keep of a policy-kept episode makes it manual (W-INV-023). Per-feed **Match rules** (behind a row in the same popover) are ordered include/exclude patterns that Keep or Skip, first match wins. The preview lists every current episode's verdict and, separately with counts, what **Apply to existing** would change. Compact previews keep the number of affected episodes and the audio deletion warning beside Apply while results scroll. Apply re-evaluates undecided and automatic decisions only, never manual or started (playing or part-heard) episodes, respects the kept limit, and starts the downloads and preparation the feed's policy calls for; **Undo** restores the prior decisions and queue and takes back work that has not started. The resolver and planner are in `Producer/Sources/WiltedProducer/Automation/`; the Mac side is `EpisodeAdmissionService` and `WiltedMacModel+FeedDecisions.swift`.

**Test preferences.** Mac unit tests never use the app's `UserDefaults`. `WiltedMacTestPreferences.ephemeral()` and `suiteName(_:)` give every request a suite named by test-process ID and UUID, so concurrent test hosts cannot wipe each other's state, and an observer removes each suite and its plist when its test case finishes. A relaunch-style test keeps the one `UserDefaults` it was given for both models.

## Host-read recovery

`wilted_worker/boundary_review.py` owns positive programme evidence: `record_programme_boundary` records reviewed programme/mixed cues in the existing `HeldAdSpan` ledger, and `overlaps_programme_boundary` applies the shared interval geometry. Candidate review, mixed-tail trimming and credits-head trimming use that recorder; candidate review, late-start recovery and the final conflict guard use that overlap decision. The final guard remains in the shared live/replay analysis path. Unknown reviews, released edge intervals, dropped-anchor accounting and evidence containment retain their distinct policies. Per-feed placement memory remains an unimplemented nomination proposal in TASKS, not cut authority. This consolidation preserves prompts, cut decisions and engine v13 semantics; the normal source fingerprint distinguishes the code revision without invalidating prepared audio.

Preparation recovery requests every journalled run independently of Prep's 200-run display limit; the existing journal query already decodes the full history before applying that display cap. A playing revision's cut timeline first uses the recent 64-row scan, then an exact current-outcome lookup and the bounded Ready-generation proof when newer failures bury its success. These reads do not prune history or change the schema; storage indexing and retention remain separate decisions.

Host-read recovery no longer depends entirely on a known sponsor-opening phrase. Adjacent call-to-action and destination evidence, including phrases split across cue boundaries, can nominate a bounded envelope; one constrained review selects a contiguous commercial subset containing that evidence, and an independent proposal-focused programme review sees every character of the proposed cut, labels each proposed cue and two cues either side as commercial, programme, or mixed, vetoes any programme or mixed cue, and requires programme on both sides. A proposal that is only the first spot of a longer pod has commercial cues beside it, so the review labels up to three more pairs outward on that side before declining; the pod continuation then extends the cut to the programme. Asking the model to list which proposed cues were programme had it list all of them, and a Planet Money pod of three spots played. A candidate whose complete text cannot fit the review budget is preserved rather than reviewed from a truncated excerpt. Explicit recovery verifies every cue from its anchor through its commercial evidence, including at transcript start, so CTA and destination signals cannot accumulate across intervening editorial speech; a consecutive opening pair separately requires its dedicated prefix proof. An episode-wide extra-call cap, duration/share bounds, overlap rejection, and fail-closed parsing limit the unanchored path; reads with neither an explicit opening nor CTA/destination evidence remain outside it.

Short, isolated commercial evidence can also nominate a pause-bracketed host read for a bounded review. The pause only proposes boundaries: the detector reads the complete passage, requires programme on both sides, and preserves any cue judged programme or mixed. If the read begins ambiguously, it may cut a separately confirmed commercial suffix while leaving that opening audible. A separate continuation check can retain consecutive opening ads before the first programme cue. These paths have model-call and duration limits, and an invalid or uncertain review keeps the audio. The September 24 Weekly Show prepared-copy diagnostic now removes the full Shopify, ChatGPT, and Smalls labelled spans plus most of Ground News and Bombas; its conservative review leaves 10.9 and 14.2 seconds of those two openings. The missing original aligned transcript and dynamically changed enclosure prevent claiming an exact replay or a repair of the currently playing revision.

Candidate spans receive a bounded independent programme review before either the single-span or aggregate unreviewed-share guard would refuse them. A reviewed fragment stays within the original numeric proposal, may rebase only to an explicit anchor inside it, and must expose every proposed word to a fresh confirmation. Positive programme or mixed cues remain whole and become keep barriers for subsequent candidates and pod recovery. Closing credits receive a separate first-cue check so a shared conclusion or sign-off stays audible. A confirmed kept cue resolves only commercial evidence fully contained by that cue; unanswered reviews never resolve commercial evidence.

Coverage checks accept one adjacent floating-point value of endpoint drift, including the observed 167.32-second join, while genuine gaps stay uncovered. The 50% unreviewed limit, 60% total ceiling, programme floor and original-audio fallback remain unchanged. A later cut crossing a positive programme barrier, an unanswered review, or an unresolved commercial seed that a cut overlaps preserves the whole original and reports uncertainty; an unresolved seed no cut overlaps, including one directly beside a cut, stays audible on its own while the other cuts apply. The worker provenance is podcast-preparation-v12; existing prepared revisions are not invalidated. Labelled quality replays and actual-audio preparation timings are reported separately when the historical audio is missing.

## Silence trimming

When ad removal is on, preparation also shortens long pauses. `wilted_worker/silence_trim.py` runs one ffmpeg `silencedetect` pass over the original audio (noise floor -50 dB, pauses of 0.25 s or more; the floor is justified in `constants.py`), reporting a heartbeat, and subtracts the excess from the keep map: a pause longer than 0.5 s keeps only its first and last 0.25 s (a pause of 0.5 s or less is left alone), and silence at the very start or end of the episode goes entirely. Pauses are measured on the ad-cut clock, so a pause that an ad cut joins together is trimmed once, and the keep map stays within 500 intervals by trimming the longest pauses first.

Trimmed pauses are never ads. The ad spans remain the complement of the ad-only keep map; the pauses travel in the result's separate `silenceTrims` list and never enter `adSegments`, `removedSeconds`, the ad lifetime statistic or the timeline's removed list. An episode whose only change is shorter pauses reports `noAds` with changed audio, and the Swift decoder accepts that only with a non-empty `silenceTrims` that, together with the ads, exactly fills every gap in the keep map. A saved position inside a trimmed pause resumes where the speech does. Disabled and uncertain results are never trimmed (W-INV-013). A detection failure keeps the pauses, and a failed silence-only render keeps the original audio; both report an `audio.silence.skipped` warning and the episode is still prepared. The worker provenance is podcast-preparation-v12; already prepared revisions are not re-processed.

## Conventions

- A reported ad-detection failure becomes a corpus case before it becomes a fix; the corpus stores labels and pointers, never episode audio or transcript text.
- UX changes are designed and reviewed in the native app itself; do not build HTML prototypes or mockups as a gate before native work.
- Keep all Wilted-owned project files self-contained under this directory. The preparation runtime may use only its documented shared `~/Documents/Projects/speech-stack` prerequisite; the reference-only archive is not an active dependency.
- Secrets belong in BWS and never in committed files.
- UI code does not write producer state directly; shared domain contracts own identity, transfer, and playback reconciliation.
- Native UI follows the canonical Zero Delta structure with Wilted's restrained lettuce identity; use literal navigation labels and reserve semantic colors for state.
- Where an SF Symbol clearly stands for a one- or two-word status or action (play, skip, remove, download, retry, played, in progress), the icon is the default: icon-only, with the word kept as its tooltip (`.help`) and in its accessibility label. Phrases, counts, and anything without an unambiguous symbol stay text.
- Wilted's own symbols live in `Shared/WiltedSymbols.xcassets` as SF Symbols variable templates (exported from the SF Symbols app; both targets compile the catalog) and are named through `WiltedSymbol` in `Shared/WiltedSymbols.swift`: the larder for the Larder, the cutting board for Prep, the food processor for a preparation in progress, lettuce for an article, cabbage for an episode, broccoli for a feed, the basket for a manual playlist and the colander for a smart one (these two were generated in the same template from outline drawings at the produce symbols' 3.6-unit line, and can be redrawn in the SF Symbols app). `Image(symbol:)` and `Label(_:symbol:)` take either a `wilted.` name or a system name, so a `symbolName` string can be either. A symbol added to the catalog must be added to the enum; `testCustomSymbolsResolveFromTheCatalog` in both unit targets fails on a name the bundle cannot resolve.
- Pixel baselines are re-recorded with `scripts/record-mac-snapshots.sh [method ...]` and `scripts/record-ios-snapshots.sh [method ...]`; both build from a copy under `$TMPDIR`, as the gate does. Record mode keeps a Mac baseline that still matches 99% of its pixels; `WILTED_FORCE_RECORD_SNAPSHOTS=1` rewrites the named methods' baselines anyway. The Mac recorder continues to copy its PNGs back so `git status` shows exactly what moved. The iOS recorder makes fresh requested PNGs and publishes the complete requested set atomically only after every requested output succeeds; it preserves unrequested baselines and all prior bytes on recording failure, with failed-case diagnostics. The Mac daily-driver walkthrough is captured with `scripts/record-walkthrough-frames.sh`, built into an HTML report by `scripts/build-mac-walkthrough.py`, and audited by `scripts/audit-walkthrough.sh`.
- Update `HISTORY.md` alongside meaningful changes and keep pending work in `TASKS.md`.
- `LocalLibraryStore`'s SwiftData schema is versioned (`LocalLibrarySchemaVersion`, currently V21, with V19 adding durable manual-completion receipts, V20 adding confirmed same-feed association records and V21 dropping the retired sync engine's tombstones, repository state and unused sync columns; see "Installing and the library publisher" below for the historical V14 statistics migration) and every version-bumping change adds a brand-new frozen model class rather than mutating a shipped one, migrating through `LocalLibraryMigrationPlan`'s lightweight stages. V10 adds `PodcastPreparationOutcomeRecord` (revision-scoped preparation eligibility/provenance), `PodcastListeningRecord` (item-scoped listening completion), `PodcastEpisodeRecord.retiredAt`, and `PodcastDownloadRecord.failureKind`. An idempotent `reconcilePodcastStateV10()` backfills preparation outcomes and listening records from pre-V10 durable state (journal entries, `PlaybackRecord`s, and legacy invalidation markers); `WiltedMacModel.performStoreBootstrap()` calls it on every launch, before `invalidateStalePodcastPreparations`, so a store owner does not call it explicitly. `retiredAt` and `failureKind` have no pre-V10 history to backfill and simply start `nil`. See `INVARIANTS.md` W-INV-011.
- `PodcastPreparationPipeline`'s `semanticFingerprint` (`semanticVersion` + the worker entry, its `wilted_worker` package and the resolved Python dependency sources, hashed at launch) identifies which pipeline version produced a stored preparation outcome, but a fingerprint mismatch on its own invalidates nothing: `invalidateStalePodcastPreparations` only acts on episodes an explicit `PodcastPreparationInvalidationRule` in `PodcastPreparationPipeline.invalidationRules` matches, and that table starts empty. Add a rule only when a specific pipeline change actually made prior output wrong; an unrelated refactor, comment, or logging change should never force a redownload or re-preparation. `semanticVersion` is bumped by hand when preparation behavior changes; there are no checked-in source-hash pins to update. `WiltedMacModel` takes its rule table via an `invalidationRules` init parameter defaulting to the production table, so tests can inject a scenario-specific rule without changing what ships. A rule's `.forceRedownload` consequence is admitted one at a time through a detached bootstrap-recovery task (not inline in `performStoreBootstrap()`), so a library-wide migration with many stale episodes cannot open N simultaneous transfers and cannot hold the app in a non-ready state for the whole recovery burst; `waitForPodcastOperations()` is the test seam that waits for that task to drain.
- The 0.2.8 ad-recovery worker records `podcast-preparation-v4` with refreshed worker and Swift source hashes. Existing prepared audio remains eligible because the production invalidation-rule table is empty; a listener who wants the new detector on a particular episode must explicitly request a new preparation, redownloading first if the current audio was cut.
- `HISTORY.md` and `TASKS.md` are local operational documents and are ignored by Git.
- Every podcast download, podcast preparation, and article preparation request is durable: `LocalLibraryStore` keeps one `WorkTicket` row per `(kind, subjectID)`, moving through `pending`/`deferred` (admitted, not yet running) → `running` → a terminal state (`succeeded`/`failed`/`cancelled`). `WorkTicketState.canTransition(to:)` only allows forward movement within one request sequence; `readmitWorkTicket` atomically replaces a settled attempt’s policy and stale failure/run fields for a newer sequence, while late older writes are ignored and duplicate running writes count only once. `applyWorkTicketTransition` does the whole find/validate/mutate/save as one actor-isolated call with no `await` in the middle -- the actor itself is what serializes two Tasks racing to transition the same subject, given a conflicting insert on `@Attribute(.unique)` measurably throws on neither side and would otherwise lose a write silently. An article's `subjectID` is `ItemID.derive(from:)` the pasted draft URL -- pure and networkless, so it is stable at request time -- and its `resolvedItemID` is stamped once extraction returns the canonical URL, which a draft link and the canonical article it redirects to can disagree on. `reconcileWorkTickets(in:)` runs on every launch, before the library loads: it imports preferences-held off-peak deferrals and orphaned podcast downloads as tickets, closes any ticket left `running` by a process that is not this one (retried as `pending`, or failed once its attempt budget is spent), collapses an article-preparation duplicate that another draft URL's ticket already resolved to the same `resolvedItemID` (keeping the most recently requested, cancelling the rest), and prunes terminal tickets older than 30 days while always keeping at least the newest 50 per kind. A ticket-drain ticker (`startTicketDrainTicker`, distinct from `startAutomationTicker`) evaluates admission for whatever non-terminal tickets exist on a fixed interval and, unlike the open-window tick, keeps running while the window is hidden -- `checkpointForBackground` never stops it, only actual termination does -- because an off-peak window opening behind a hidden window used to go unnoticed until the window came back.

## Build cache and scratch

Run SwiftPM and Xcode builds through `python3 scripts/build-with-cache.py run <swiftpm|xcode> <label> -- <command>`. Both kinds clear cached File Provider metadata before building (SwiftPM the whole package cache, Xcode only the cache's `Build` tree, so the shared installer cache never touches another leg's DerivedData) and, on a detritus signing failure, clear again and retry once within the shared work budget, reporting `native.xattr.retry`. Raw `swift build`, `swift test` or `xcodebuild` calls outside the helper get no such protection. The helper reuses stable package caches under `.build/swiftpm/<label>` and one `.build/xcode` DerivedData in this worktree, serializes builds sharing a cache, and reports waits. Use `path` to inspect a cache without building. Temporary diagnostics use a marked `mktemp -d` directory under `$TMPDIR` and are removed at exit; cited evidence and tool runtime logs live in gitignored `.logs/`, and the Mac app's own warning log lives in its state directory (`WiltedMac/WiltedMacLogArchive.swift`). Phase 0 records identity-based before/after entry sets for the inherited TMPDIR and each contained test leg, so a new `wilted-*` entry fails even when older entries disappeared. The crash sweep removes only marked, inactive owned roots after its age cutoff. The audit attributes a new entry whose owner marker names a live process other than this run to that owner (`temp.foreign`), so a concurrent gate in another worktree is not this run's leak; an unmarked entry or one whose owner has exited is. `python3 scripts/check-no-global-tmp.py` checks operational scripts and docs, and in shell sources rejects `mktemp -t` and template-less `mktemp` (macOS puts both in the shared per-user temp root, ignoring `TMPDIR`) and any top-level `$TMPDIR/wilted-*` root that is not a `mktemp -d` directory marked by `wilted_temp_mark_owned` on the same line. `python3 scripts/check-log-conventions.py` checks that every shipped `Logger` uses a `com.zerodelta.wilted` subsystem and a PascalCase category, so `/usr/bin/log show --predicate 'subsystem BEGINSWITH "com.zerodelta.wilted" AND processImagePath BEGINSWITH "/Applications/"'` finds every installed app's lines. On every exit outside its self-tests, `scripts/test-gate.sh` runs `python3 scripts/sweep-test-preferences.py`, which removes the `com.zerodelta.wilted.mac.tests.*` and `com.zerodelta.wilted.mac.ui-fixture.*` plists of exited Mac test hosts from `~/Library/Preferences`; a running host keeps its own, and a reused PID does not count as running.
