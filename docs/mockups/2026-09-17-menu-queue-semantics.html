MOCKUP — NOT THE SHIPPING APP

Menu

The Menu is the list of episodes still to be played — one list, one set of actions, nothing shown twice. Finish an episode and it leaves. Skip it and it leaves. An episode started and left unfinished has not been played, so it stays in place and resumes where it stopped. Everything here is reachable and removable; nothing is hidden behind a playback position.

Every action on this screen is reversible from the banner above it. Nothing here deletes audio, a prepared cut, a transcript, or a listening record.

PROPOSED

One list. Every episode still to be played, in Menu order, each with the same single action. Sorting reorders the list; the episode playing now holds its place because you are in the middle of it.

Skip removes it from the Menu and nothing else. The episode keeps its identity, downloaded media, prepared cut, transcript and listening record. Undo is local, so it works with no network.

Clear upcoming empties the list but leaves the unfinished episode you are listening to, and offers one Undo that restores the whole set in its original order.

Drag the grip to reorder, including onto the strip below the last row, which is a real destination. A drag is an explicit order, so it drops any calculated sort rather than being erased by the next redraw. A payload that is not one of this Menu's episodes is refused and the order is left alone.

The last position is unreachable. moveMenuEpisode(_:before:) names its destination by the ID of the row to insert before, and there is no row after the last one, so nothing can be dragged to the end. menuInsertionIndex has no end-of-list convention, and no drop handler checks that the payload is a known episode ID.

A STRANDED ENTRY IS A FAULT, NOT A SEMANTIC

A played episode should never be on the Menu. When one is, removePodcastQueueEpisode failed and try? swallowed the error, or refreshPodcastQueueState returned early on an unreadable store. The episode is retired and hidden, yet still holds a Menu slot.

The code already compensates: nextMenuEpisodeToPlay skips the just-finished ID rather than trusting the head of the queue. That guard is a workaround for this fault. Fixing it is error handling, and it is not a reason to change what the Menu shows.
