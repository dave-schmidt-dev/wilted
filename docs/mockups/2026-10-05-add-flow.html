Add flow and catalogue

Q012 (one Add control) and Q015 (global podcast catalogue). Static mockup, synthetic data. Nothing here is built; David selects an option or defers the area.

Both ask for the same entry point: one Add that handles podcasts, article feeds and single articles, with catalogue search so no one has to find an RSS address.

Option A: One field that classifies and searches

Add opens one sheet with one field. A pasted link is classified as you type; any other text searches the catalogue. One step to subscribe.

Data contract
  • AddClassification: podcastFeed | articleFeed | article | unsupported(reason), from one URL, decided by fetching and sniffing the document.
  • CatalogueResult: showID, title, publisher, artworkURL, feedURL, alreadySubscribed. Provider is not chosen; the owner picks one before any build.
  • Subscription (article feed) and one-off (article) stay separate stored kinds; an article feed's new items arrive in Feeds as Keep or Skip.
  • States: classifying, searching, cancelled, stale query dropped, unreachable address, unsupported format. Already-followed shows never create a duplicate.
