# iOS listener reliability and lifetime statistics

## Outcome

Make the Mac the reliable publisher and canonical catalog owner, and make iOS a durable listener that receives, downloads, plays, and reports podcast and article progress without losing newer local work. Settings gains truthful lifetime audio statistics. The detailed, Switchyard-ready work contract is [`ios-listener-sync-reliability-2026-09-12-tasks.md`](/Users/dave/Documents/Projects/.plans/wilted/ios-listener-sync-reliability-2026-09-12-tasks.md); this document is the decision record.

## Scope and order

1. **Sync integrity first.** Unknown record types skip rather than fail a batch, through the actual transport/engine fetch path and before a new record family can make an old listener reject the batch. Static pending/protected guards cover only Mac-owned item, revision, and transcript records; new podcast types extend that classification in their own schema task. Playback records use the existing causal `mergePlayback` contract, not a skip-install rule. Acknowledgements compare the exact immutable batch sent, so an older acknowledgement cannot delete a newer queued mutation. Stage/commit retries preserve the fetched batch; retry exhaustion reconstructs a fresh Mac transport or listener session from last-known-good persisted state and retries once.

2. **Podcast publication and return path.** Add the approved podcast record shape, CloudKit mapping, ownership rule, codec, fixtures, and contract validation in one schema change. The shape includes an explicit type discriminator for playback item/revision references; no codec may infer article versus podcast from an opaque ID. The Mac queues prepared podcast publications; iOS projects the metadata, downloads the referenced audio, plays it, and sends a podcast-identity playback checkpoint. Applying that checkpoint on Mac updates its local listening projection; it does not make `PodcastListeningRecord` itself CloudKit-syncable. The contract includes explicit record/reference allowlists, byte ceilings, retention behavior, valid/invalid fixtures, and an old-listener compatibility proof.

3. **Chunk-transfer evidence before a migration.** Capture and retain a reproducible, sanitized real CloudKit trace. If eager asset transfer is refuted, record that terminal result and make no zone-layout change. If confirmed, add a resumable dual-read/republication migration for existing chunks, preserve old record identities until converted, use a non-`Reference` cross-zone parent identity, and prove metadata refresh transfers no asset bytes while explicit download succeeds. Fixture proof is not a live-account claim.

4. **Listener behavior and cache correctness.** Preserve current revision selection, persist seek/completion state with a bounded periodic background checkpoint, keep a paused seek paused (backward seek creates a rewind session; forward seek retains progress/session), expose working Now Playing controls through the real production object graph, and trigger `sendPending()` only after the active engine position is persisted on foreground and playback events. Operations serialize conflicting state mutation: deferred sends eventually run rather than disappear. Automatic CloudKit fetch remains disabled. Keep local cache cancellation, reconciliation, deduplication, and eviction bounded and tested.

5. **Lifetime statistics.** Store append-only, deterministic, deduplicated events; never backfill from mutable rows. Article synthesis earns final samples/sample-rate duration. Every successful podcast preparation earns accepted source duration, including disabled/no-ads/non-cut classifier paths; only a validated committed cut earns ad-removal duration. Mac records forward `r > 1` saved time as `p - p/r` with a per-revision high-water mark. Mac Settings shows all four counters: Audio processed, Speech generated, Confirmed ad time removed, and Time saved at faster speeds. Until an approved cross-device merge contract exists, listener Settings represents every Mac-owned total as explicitly unavailable with its reason, never as zero or an invented merged total.

6. **Closeout.** Run focused checks per task, one batched native UI/pixel pass after all Phase 11 changes, then the full gate. Task 13.1 authors required README, invariants, history, and walkthrough updates only for implemented work. No commit, release, install, CloudKit-live claim, or owner acceptance is implied by this plan.

## Holds

- Podcast revision/chunk record shape is David's decision and must specify the playback type discriminator, reference allowlists, version/old-listener rule, and evidence fixture. A live CloudKit test account is required for live trace only, not fixture validation. The hash-cost decision requires a reproducible fixture, device/OS capture, command, measured duration, and threshold. Cross-device statistics require David's merge contract covering event identity, conflict/retention, migration, old-client compatibility, and authoritative scope. Local zeroes or invented totals are forbidden.
